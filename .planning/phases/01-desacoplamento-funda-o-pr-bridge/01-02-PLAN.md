# Plan 01-02: Migração de Banco de Dados para pr_lib.db

## Objective
Migrar a criação de schemas, verificação de colunas e todas as consultas e operações SQL de `sv_utils.lua` e do legado `insert.lua` para o módulo unificado `pr_lib.db`, utilizando o `AUTO_INCREMENT` nativo para novas bancadas e suportando qualquer driver de banco automaticamente.

## Proposed Changes

### 1. Novo módulo de banco `sv_db.lua`
- Criar `sv_db.lua` executado no lado do servidor.
- Registrar evento de inicialização `onServerResourceStart` ou chamada inicial garantindo a criação de tabelas:
  - `CREATE TABLE IF NOT EXISTS forge-crafting (...)`
  - `CREATE TABLE IF NOT EXISTS forge-crafting-items (...)`
- Utilizar `pr_lib.db.execute` para verificar e adicionar colunas ausentes (`model`, `anim`, `level`) caso não existam.

### 2. Refatoração de Queries em `sv_utils.lua`
- Substituir `MySQL.Async.fetchAll('SELECT * FROM forge-crafting WHERE craft_name = @craft_name', ...)` por `pr_lib.db.single('SELECT 1 FROM `forge-crafting` WHERE craft_name = ?', { name })`.
- Substituir `MySQL.query('SELECT * FROM forge-crafting', ...)` por `pr_lib.db.query('SELECT * FROM `forge-crafting`', {})`.
- Substituir `MySQL.query('SELECT * FROM forge-crafting-items WHERE craft_id = ?', ...)` por `pr_lib.db.query('SELECT * FROM `forge-crafting-items` WHERE craft_id = ?', { craft_id })`.
- Ajustar `forge-crafting:CreateWorkShop`:
  - Remover `local craft_id = math.random(1, 1000000)`.
  - Executar `pr_lib.db.insert` sem passar `craft_id` para aproveitar o auto-increment do MySQL.
- Atualizar mutações de renomeação e exclusão:
  - `UPDATE forge-crafting SET craft_name = ? WHERE craft_id = ?` via `pr_lib.db.execute`.
  - `DELETE FROM forge-crafting WHERE craft_id = ?` via `pr_lib.db.execute`.
  - `DELETE FROM forge-crafting-items WHERE craft_id = ?` via `pr_lib.db.execute`.

## Verification Plan

### Automated / Code Inspection
- Garantir que nenhum arquivo contenha `MySQL.Sync`, `MySQL.Async` ou `MySQL.query`.
- Verificar se todas as consultas utilizam placeholders parametrizados `?` suportados pelo `pr_lib.db`.

### Functional Verification
- Verificar se o recurso inicializa no FiveM sem erros de sintaxe SQL no console.
- Verificar se a criação de bancadas persiste no banco e recebe um `craft_id` sequencial correto.
